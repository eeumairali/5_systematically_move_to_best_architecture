Classification asks what.
Re-ID asks which one.

A classifier picks a label from a fixed list it was trained on. A re-ID model never predicts your cows at all — it learns a ruler for measuring sameness, and the identities live in a database you can edit at 3am without retraining anything.

01 / FOUNDATION

CNN fundamentals

You know these. Here they are again, but read them asking one question: how does this turn a picture into a vector?

Convolution & feature maps

A conv layer is a small stack of learnable filters slid across the image. Each filter answers one question at every position — "is there a vertical edge here?" — and writes the answer into a feature map. A layer with 64 filters produces 64 feature maps: 64 different questions asked about every location.

out_size = floor((in + 2·pad − kernel) / stride) + 1 params = kernel_h · kernel_w · C_in · C_out + C_out // weights + bias FLOPs ≈ out_h · out_w · kernel_h · kernel_w · C_in · C_out

Pooling

Downsampling. Max-pool takes the strongest response in each window; it throws away where exactly a feature was and keeps that it was there. That small blindness is a feature: an animal shifted 4 pixels right should not produce a different vector.

Why you should care for re-IDPooling too aggressively destroys fine spatial detail — and fine detail (a specific ear notch, one stripe fork) is often the only thing separating two individuals. This is why re-ID backbones commonly set the last stride to 1, keeping a 16×8 feature map instead of 8×4. Small change, consistently ~1–2% rank-1.

Residual connections

A plain 50-layer stack trains worse than a 20-layer one — not from overfitting, but because gradients degrade and the optimiser cannot even find the identity mapping. The fix is to make identity the default:

y = F(x, W) + x // the block learns the *change*, not the whole function ∂y/∂x = ∂F/∂x + 1 // gradient always has a clean path home (the "+1")

Global Average Pooling — the step that makes re-ID possible

This is the hinge of the whole document. After the last conv stage you hold a tensor of shape C×H×W — for ResNet-50 at 224×224 input, that's 2048×7×7. GAP averages each channel over all spatial positions:

v[c] = (1 / (H·W)) · Σ_h Σ_w F[c, h, w] // 2048×7×7 → 2048×1×1 → a 2048-d vector

Three consequences worth memorising: input size no longer has to be fixed; there are zero parameters so nothing can overfit here; and — the important one — you now have a single vector describing the image, and vectors can be compared to each other. A classifier throws this vector into a final linear layer and forgets it. Re-ID keeps the vector and throws away the linear layer.

The one-sentence versionBackbone = image → vector. Head = vector → label. Re-ID keeps the backbone and deletes the head, because labels are a closed set and vectors aren't.

Re-ID modifications to stock ResNet-50

  • Input shape — people use 256×128 (2:1, body-shaped). Cattle side-view crops are wider; 256×256 or 224×224 is the sane starting point. Pick one and never change it again, or your results table becomes meaningless.
  • Last stride = 1 in conv5_x → feature map 16×16 instead of 8×8. More spatial evidence into the GAP.
  • Embedding neck — optionally fc(2048→512) to shrink the vector. Cheaper storage, faster search, slight accuracy cost.
  • ImageNet init — always. Random init on a small animal dataset is a wasted week.
03 / THE OBJECT

Embeddings

A list of numbers whose only job is that geometry means something.

An embedding is the GAP output (optionally projected down): a point in a 512- or 2048-dimensional space. On its own it is meaningless — 512 arbitrary floats. It becomes an embedding when the training procedure has enforced one property:

‖ f(x_i) − f(x_j) ‖ is small when i and j are the same individual ‖ f(x_i) − f(x_j) ‖ is large when they are not …and that's the whole contract. Nothing else is promised.

Feature space, drawn honestly

You cannot see 512 dimensions, so every diagram (including mine) cheats by showing 2. Keep the cheat in mind: in high dimensions there is far more room, distances concentrate, and clusters can be separated in ways that look impossible on paper.

Choosing the embedding dimension

dimBehaviourUse when
128Fast, tiny index, underfits with many identities< 200 individuals, edge device
256–512The sweet spot in nearly every published re-ID paperStart here
2048Raw ResNet GAP output, 4× storage, marginal gainYou have not yet added a neck

Storage arithmetic for your ablation table: 10,000 embeddings × 512 dims × 4 bytes (fp32) = 20 MB. Nothing. 10 million × 2048 = 80 GB. Something. Dimension is a deployment decision as much as an accuracy one.

Always L2-normaliseDivide each vector by its norm so every embedding sits on the unit hypersphere. This makes Euclidean distance and cosine similarity monotonically equivalent (d² = 2 − 2·cos), makes one global threshold meaningful across the whole gallery, and stops the network from cheating by inflating vector magnitude instead of improving direction.
04 / THE ENGINE

Metric learning

The loss function is the whole idea. Everything else is plumbing.

Contrastive loss — pairs

L = y · d² + (1 − y) · max(0, m − d)² y = 1 same individual, y = 0 different, d = ‖f(x₁) − f(x₂)‖, m = margin

Same pair: pull together, with no floor — it wants d → 0 absolutely. Different pair: push apart until d ≥ m, then stop. That asymmetry is the flaw. Forcing every positive pair to collapse to a single point is a harsher demand than the task requires, and the margin m is a global constant applied to identities that legitimately differ in how tight they should be.

Triplet loss ⭐ — relative, not absolute

Three images per comparison: an anchor, a positive (same individual), a negative (different individual). It never asks for an absolute distance. It only asks that the positive be closer than the negative, by at least a margin.

L = max( 0, d(a,p) − d(a,n) + margin ) satisfied → loss 0 → zero gradient → that triplet teaches nothing
Why triplet beats contrastive — and why it matters to youRelative ordering is what retrieval actually needs: at query time you rank the gallery, you never check an absolute distance. Schneider et al. tested exactly this across five species — humans, chimps, humpback whales, fruit flies, and ATRW tigers — and triplet loss beat contrastive loss for every architecture on every dataset. On ATRW, ResNet-152 went from 0.877 to 0.996 mAP@5. That result is in your project folder; it is the single strongest empirical reason to skip contrastive loss entirely.

The batch-hard problem

Random triplets die fast. After a couple of epochs most randomly sampled triplets already satisfy the margin, so their loss is exactly 0 and they contribute nothing — you burn GPU time computing gradients that are zero. The fix is batch-hard mining:

PK sampling — build each batch as P identities × K images. Typical: P=16, K=4 → batch 64. For every image in the batch, used as anchor: positive = the hardest (furthest) same-ID image in the batch negative = the hardest (nearest) different-ID image in the batch L_BH = (1/PK) Σ_a max(0, max_p d(a,p) − min_n d(a,n) + margin)

Every anchor now contributes a genuinely difficult triplet. Note it only mines within the batch — so batch composition is a hyperparameter, not an implementation detail.

Failure mode: collapseIf margin is too large or the learning rate too high, the cheapest way to satisfy the loss is to map every image to the same point. Loss goes to a constant, distances go to zero, accuracy is chance. Watch mean d(a,p) and mean d(a,n) as separate logged metrics — if both trend to 0, you have collapsed. Soft-margin L = log(1 + exp(d_ap − d_an)) is the usual escape hatch.

If you L2-normalise (and you should), the choice stops mattering mathematically: d² = 2 − 2·cos(θ), so ranking by one is identical to ranking by the other. Use cosine anyway, because 0.82 is a number you can reason about and 0.6 Euclidean units is not.

The similarity threshold τ

Training gives you a ruler. τ is where you decide to cut it. It is not learned, it is chosen on a validation set after training, and it encodes a business decision: is it worse to merge two cows into one record, or to invent a new record for a cow you already have? 05 / ARCHITECTURE

OSNet — omni-scale feature learning

Zhou et al., ICCV 2019. Purpose-built for re-ID, and about 10× smaller than ResNet-50.

The problem it solves

Identity evidence lives at several scales at once, and they are not interchangeable. For a cow: a specific patch shape is small-scale; the arrangement of patches across the flank is medium-scale; overall body proportion and coat layout is large-scale. A standard ResNet block has one receptive field per layer, so it commits to a scale at each depth. OSNet refuses to commit — it computes multiple scales in the same block and learns how to weight them per input.

The building blocks

Lite 3×3. A depthwise-separable convolution, ordered pointwise-then-depthwise: 1×1 conv to mix channels, then 3×3 depthwise for spatial extent. Costs roughly 1/9 of a standard 3×3 at the same channel count. This is why OSNet is ~2.2M parameters against ResNet-50's ~25.6M.

The omni-scale residual block (OSBlock). T parallel streams. Stream t is a stack of t Lite 3×3 layers, so stacking grows the receptive field: 1 layer → 3×3, 2 → 5×5, 3 → 7×7, 4 → 9×9. Four scales, computed simultaneously, from the same input.

Unified Aggregation Gate (AG). The part that makes it "omni-scale" rather than merely "multi-scale". A tiny sub-network (GAP → FC → ReLU → FC → sigmoid) produces per-channel weights, and the same AG is shared across all T streams. The streams are summed with input-dependent weights instead of being concatenated with fixed ones — so a blurry distant frame can lean on large-scale cues while a sharp close-up leans on fine texture, with no architecture change.

06 / TRAINING

Re-ID training

Two losses on one backbone, and the question that confuses everyone: what is the target?

Why there is no target embedding

In classification you have a target: the one-hot label. In regression you have a target: the number. In re-ID there is no target vector. Nobody knows what cow #17's embedding "should" be, and no such answer exists — any rotation of the entire space is equally valid.

The supervision is relational. The loss is a function of distances between outputs, not of an output against a stored answer. Gradients flow from the comparison, backwards through all three (or two) forward passes, into the same shared weights. The network is not learning "where to put cow 17". It is learning "what makes two pictures of one cow look alike".

The mental switchClassification: loss(output, label). Metric learning: loss(output_a, output_p, output_n). Once you internalise that the label only tells you which images are groupable — never where the group goes — the rest of re-ID stops feeling strange.

The standard recipe: ID loss + triplet loss

Neither loss alone is best. Cross-entropy on identity labels gives fast, stable convergence and learns strongly discriminative features — but it optimises separability in the classifier's space, not distances in the embedding space. Triplet loss optimises exactly the geometry you deploy, but converges slowly and is fragile alone. Everyone uses both.

L_total = L_ID + λ · L_triplet // λ = 1.0 is the near-universal default L_ID = cross-entropy( fc(f), y ) // N_train_ids outputs; discarded at test time L_tri = max(0, d(a,p) − d(a,n) + m) // batch-hard, on the embedding itself

BNNeck — the detail that quietly wins 2–3%

The two losses want incompatible feature geometries: cross-entropy prefers features spread out along class-specific directions, triplet prefers them compact on a sphere. Applying both to the exact same vector makes them fight. BNNeck (Luo et al., "Bag of Tricks") separates them with a BatchNorm layer:

Metrics — report these, always

  • Rank-1 (CMC top-1) — fraction of queries whose nearest gallery neighbour is the right identity. The headline number.
  • Rank-5 — right identity anywhere in the top 5. Forgiving; useful for human-in-the-loop workflows.
  • mAP — averages precision over all correct matches, not just the first. Rewards a model that retrieves all 20 images of a cow, not just one lucky one. Always report it alongside rank-1; a big rank-1/mAP gap means the model gets lucky rather than being reliable.
Protocol disciplineQuery and gallery identities must not appear in training. If they do, your numbers are classification accuracy wearing a re-ID costume, and the model will fail on the first new cow. Split by identity, never by image.
07 / DEPLOYMENT

Inference pipeline

Training is over. The head is gone. Here is what actually runs.

Practical notes

  • One embedding per identity, or many? Many. Store every good crop, then score a query against an identity by the mean of its top-3 similarities to that identity's embeddings. Far more robust than a single centroid, and Schneider et al. found multi-image comparison per individual measurably improves cattle re-ID.
  • Batch your crops. One forward pass over 32 crops from a frame, not 32 forward passes.
  • Cache aggressively. Gallery embeddings are computed once. Only queries are live.
  • Quality gate first. Cheap rejects — tiny box, high blur, box touching frame edge — before the backbone. Bad crops produce confident wrong matches, which are worse than no match.
08 / OPEN-SET

Open-set and new animals

Closed-set says "which of these 40 cows is it". Open-set says "is it even one of them". Only the second one is a farm.

A softmax classifier is structurally incapable of this. Its outputs sum to 1, so a brand-new cow is forced into an existing class, usually with high confidence. This is the single strongest argument for the embedding approach and it is worth stating plainly in your write-up: re-ID handles new individuals because identity lives in a database, not in the weights.

Choosing τ

Compute similarities on a validation set for two populations — pairs from the same individual, and pairs from different individuals — and plot both distributions. τ is where you cut between them, and the overlap region is your irreducible error.

Which error do you prefer?

ErrorMeansConsequence on the farm
False acceptDifferent cows merged into one recordSilent, corrupting. Two animals' behaviour data blended; the mistake propagates and is hard to detect later.
False rejectKnown cow enrolled as newVisible. Gallery grows with duplicates, but records can be merged afterwards.
Set τ highFor a livestock ID database, false accepts are the expensive error. Bias τ towards rejecting, accept the duplicates, and add a periodic merge pass that clusters gallery entries with very high mutual similarity. Report TAR@FAR=1% alongside rank-1 — it is the metric that reflects this decision, and rank-1 alone hides it completely.

Enrolment loop

1. embed query crop → v 2. s = max similarity over gallery 3. if s ≥ τ_high → assign that ID, append v to its set (if quality is good) elif s < τ_low → create new ID, seed gallery with v else → hold in a pending buffer; ask a human, or wait for more frames of the same track and vote

The two-threshold band is what turns a brittle binary decision into a system that degrades gracefully. Track-level voting is nearly free once you have tracking (§10) and it removes most single-frame errors.

Gallery driftCattle change: coats moult, animals grow, mud happens. If you only ever store enrolment-day embeddings, accuracy decays over months. Append recent high-confidence embeddings and cap each identity at, say, 50 vectors with a recency-weighted eviction policy. Log the date on every embedding so you can measure the drift instead of guessing at it.
09 / SCALE

Large-scale search

Honest framing: at your scale you do not need this yet. Know when you will.

Brute-force search is a matrix multiply: query 1×512 against gallery N×512. On a GPU this is trivially fast until N gets large.

Gallery sizeBrute force (512-d)Do this
< 10k< 1 msnumpy dot product. Genuinely. Stop here.
10k – 1M~msfaiss.IndexFlatIP — still exact, just fast.
1M – 100Mtoo slowIndexIVFFlat or HNSW — approximate.
> 100M—IVF+PQ (compressed) or a hosted vector DB.

FAISS in four lines

import faiss, numpy as np faiss.normalize_L2(gallery) # in-place; makes IP == cosine index = faiss.IndexFlatIP(512); index.add(gallery) D, I = index.search(query, k=5) # D = cosine sims, I = row indices

The three index families

  • Flat — exact, no training, no accuracy loss. Memory = N × d × 4 bytes.
  • IVF — k-means partitions the space into cells; search only the nprobe nearest cells. Needs a train() call on representative vectors. nprobe is your speed/recall dial.
  • HNSW — a navigable small-world graph. Excellent recall, high memory, no training step. Usually the best default when Flat stops being viable.

PQ (product quantisation) is orthogonal: it compresses each vector into a few bytes, trading accuracy for 10–30× memory reduction. Combine as IVF+PQ only when RAM is the actual constraint.

Where the real cost isProfile before you optimise. At farm scale the bottleneck is the detector and the crop pipeline, not the nearest-neighbour search. Reaching for FAISS early is optimising the 0.3% — a classic way to lose a week.
10 / APPLICATION

The cow project

Where every previous section lands.

Tracking ≠ re-ID, and conflating them is the classic mistakeTracking links boxes across consecutive frames, mostly using motion (IoU, Kalman) — it survives seconds. Re-ID links identities across occlusions, cameras, and days using appearance — it survives months. JDE and FairMOT, both in your project folder, are exactly the architectures that fuse the two: one backbone, a detection head and a re-ID embedding head sharing features. FairMOT's central argument is that anchor-based detection heads corrupt the embedding head (features get sampled at anchor centres that don't align with object centres), which is why it uses an anchor-free CenterNet-style detector. That is the same argument that puts CenterNet on your roadmap before the JDE merge.

Why cattle are harder than tigers

FactorATRW tigersYour cattle
Pattern distinctivenessHigh — stripes are near-uniqueVariable. Holsteins have usable patches; solid-coloured breeds may have almost no visual signature
ViewpointMostly side-onOverhead, side, rear — and top-down looks nothing like side-on

Plan for the honest failure caseIf your breed is uniformly coloured, appearance re-ID may hit a ceiling no architecture fixes — there is simply no signal in the pixels. Test this early with a cheap experiment: embed a few hundred crops with an ImageNet-pretrained ResNet, cluster, and see whether same-animal crops group at all. If they don't, you need ear tags, RFID, or top-down body-shape features in the loop, and it is far better to learn that in week 2 than week 20.
